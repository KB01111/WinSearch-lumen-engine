# WinSearch 1.0: full DigUp feature parity on Windows

Status: proposed design for user review. Implementation has not started.

## Objective and reference

Deliver the complete Windows feature set of ARahim3/DigUp and the existing
WinSearch roadmap in one reviewable PR. The user explicitly selected the full
roadmap, including PDF, audio/video, and the expanded explorer. The similarly
named bingmann/digup checksum utility is not the reference.

Reference snapshot: [ARahim3/DigUp at ec289732](https://github.com/ARahim3/DigUp/tree/ec28973268b81f836be72187ff23b3a16ef4fd97).
The reference README, native/portable extraction, shell, tests, and evaluation
files define observable behavior; WinSearch keeps its Rust engine and WinUI 3
frontend. macOS/Linux packaging and platform-specific shortcuts are outside
this Windows app's scope.

## Audit of the current app

Baseline: main at `530320c`, with PR #1 merged. The separate
`.worktrees/phases-3-7` checkout contains 11 modified files with earlier review
fixes; they must be reviewed and ported without resetting that checkout.

What works in source: exact name/path search, application catalog, calculator,
Windows Settings search, named-pipe protocol, durable crawl queues, file
watching, model download/import, text/image embeddings, OCR/document extraction,
and a basic overlay/tray/settings frontend.

Confirmed release gaps, ordered by impact:

1. **No selection of indexed folders.** `winsearchd/main.rs::default_roots`
   immediately selects standard profile directories; Settings has no Folders
   control. A first launch can read folders before the user selects them.
2. **PDFs lack page-level processing.** `ExtractorRegistry::default` registers
   `DocumentExtractor` for PDF. That path uses IFilter and has no durable page
   cursor, page images, scanned-page OCR, or first-30-pages pass.
3. **Audio and video content is absent.** Their extensions enqueue jobs, but
   the registry has no extractor. `EmbedRuntime::embed_audio` always returns
   an error. These files are currently searchable by name only.
4. **Code is indexed only as a library foundation.** The code store/parser
   exist, but code queries are excluded from the main semantic pass and do not
   have a working opt-in scheduler/query/editor flow.
5. **The UI cannot consume location-aware results completely.** `ResultActions`
   opens the file itself, without PDF-page/media-time/editor-line routing.
   There is no expanded explorer, preview player, or onboarding flow.
6. **Index policy is incomplete.** EngineConfig contains semantic/backend
   preferences only. There is no user pause, AC/battery policy, schedule,
   configured content exclusions, or opted-in code-root control.
7. **A build is not a complete distribution.** The app's CopyEngine target
   copies only winsearchd.exe. There is no release assembly for the embed
   executable, native inference DLLs, extraction dependencies, notices,
   self-contained .NET payload, installer, or update feed handling.
8. **Some safety/recovery fixes are still outside main.** The earlier edits
   cover stale Enter queries, overflow generations, extension renames, model
   notification locks, timeout cleanup, code rename identity, path-index
   backfill, disconnected-drive retries, and model-commit compatibility.
9. **Extraction deadlines are cooperative.** In-process IFilter/native codec
   calls can outlive checks in ExtractBudget. Large/untrusted parsers need
   worker-process limits and cancellation before release acceptance.

Audit limits: this is an architecture and critical-flow audit, not a claim
that every function is defect-free. UI startup, accessibility, resource
behavior, installed-package execution, and real multimodal quality still need
fresh runtime verification.

## Approach

Recommended: complete the existing Rust/WinUI architecture incrementally. Reuse
its stores, typed protocol, extraction budgets, native worker supervisor,
WinUI controls, and source-backed reference behavior. This retains working
Windows integration and lets regression tests protect each change.

Alternative: replace the engine/frontend with the upstream Swift/Tauri stack.
That would reuse more upstream code but replace the app's architecture,
toolchain, and verified native integration. It is unnecessary for feature
parity and is not recommended.

## 1. Configuration, privacy, and recovery

Rust owns durable indexing policy and content processing. The UI sends typed
configuration requests and receives typed state. Configuration includes
normal/code roots, child-folder exclusions, extension exclusions, semantic
enablement, backend, indexing mode, manual pause, and allowed local hours.
Settings changes persist atomically and report errors. Startup registration,
theme, query memory, editor preference, and update preference are UI-owned.

Fresh installs start without content roots until onboarding commits the user's
selection. Existing indexes are preserved during migration; removed roots no
longer contribute search results or background reads. Do not modify source
files. Code search stays explicitly opt-in and separate from normal search.
Keep sensitive-file, reparse-point, and cloud-placeholder exclusions throughout
extraction, preview, and indexing. No telemetry or uploads of file data.

Port the existing uncommitted fixes after reviewing each test and root cause.
Retain stable entry identity across renames, crash-safe claims, generation
sweeps, transactional migrations, model-space invalidation, and bounded
helper cleanup. Existing tests and thresholds must not be weakened.

## 2. PDF and long-content processing

Add a PDF page reader and scanned-page OCR with bounded raster dimensions.
Prefer native Windows APIs where they meet the text/render requirements;
otherwise package an explicitly pinned PDFium runtime with its notices.
Each result carries its actual one-based page and cached thumbnail. A first
pass processes 30 pages, then durable lower-priority jobs continue in batches
up to 5,000 pages. Persist progress keyed to file identity, size, mtime, and
model compatibility, so interruption resumes and file changes invalidate
stale work. Long documents follow the same early-results/continuation model.

An external parser worker bounds file bytes, decompressed output, page/pixel
counts, segments, memory, and elapsed time. Kill and reap a timed-out worker;
one malformed file must not stall indexing. Tests distinguish unsupported
formats, temporary failures, permanent failures, and partial progress.

## 3. Audio and video

Use a pinned decoder toolchain in the private extraction worker; no shell
command construction from filenames. Decode mono PCM in overlapping 30-second
windows and feed real audio into the model's mtmd path. Carry start/end times
to the vector store and search results. Read long media incrementally with
durable cursors instead of loading the entire recording into memory.

Video combines periodic frames, shot-change frames, and the audio track.
Deduplicate nearby frame times, cap decoded frame size, and retain timestamps
and thumbnail paths. Content without an audio stream still supports visual
search. Playback previews seek to the match and show other matching moments.
Codec failure is surfaced truthfully without fabricating text or vectors.

## 4. Code search

Connect the existing repository detection, ignore rules, parser, notebook
handling, and separate code.db to a bounded background scheduler. Index only
selected code roots. Refresh after one minute of filesystem quiet; retain
durable recovery and prioritize recent changes. Match exact identifiers and
rank definitions ahead of references, then append semantic results from the
same pinned model. Preserve file and notebook-cell line numbers.

Route only explicit code mode/`code:` queries to code.db. Detect or configure
supported editors (VS Code, Cursor, Visual Studio, JetBrains, Sublime, Zed,
Notepad++); build argument lists without shell interpolation. Open the matched
file at the actual line and report unavailable editors with a usable fallback.

## 5. Windows UI and onboarding

Retain the reusable hotkey overlay and native tray. Add Space preview after
result selection, Ctrl+O expanded explorer, Ctrl+Enter reveal, and Ctrl+C file
copy where a file result is selected. Text editing shortcuts must continue to
work while typing. Keep a separate copy-path action.

The explorer shares query/category/results logic, supports list/grid views,
filters, and a preview pane. Previews include image, bounded document text,
PDF page, audio/video playback with seek, and code context. External viewer
routing uses supported page/time arguments and falls back visibly when the
viewer cannot seek. Preview work cancels when selection changes.

Provide six onboarding steps: welcome/privacy, normal folder selection and
subfolder choices, measured per-folder estimates, optional code roots, model
download/backend setup, and shortcut/finish. Model actions remain explicit;
downloads are not required for exact search. Full settings sections are
General, Search, Folders, Code, AI, Performance, Storage, and About. Tray offers
pause/resume and honest indexing state. Support light/dark/high contrast,
keyboard focus, Narrator names, and reduced motion.

## 6. Power, distribution, and updates

Pause content work according to AC/battery saver/manual/local-hours policy;
interactive exact searches continue. Idle workers block on work signals and
the inference helper exits after its idle timeout to release GPU memory.
Settings show current pause reason and storage use; cache cleanup does not
remove source files or models without an explicit matching user action.

Build a versioned, self-contained x64 Windows payload with UI, engine, embed
and parser workers, required native DLLs, notices, and dependency hashes.
Produce a per-user Inno Setup installer, optional startup registration, and
clean uninstall of app-owned installed files. User indexes/models are preserved
unless the uninstall flow explicitly selects their removal. Include signing
instructions and WinGet preparation. Signing/publishing credentials must not
be invented; an unsigned local installer is labeled honestly.

Use an opt-out daily update check against the project's version metadata,
without file names/paths or index data. Offer an explicit update action with
verified package metadata and a release-page fallback. Never silently install
an unverified payload or bypass Windows trust prompts.

## Verification and definition of done

- Red/green regressions for confirmed bugs and new nontrivial logic.
- Full Rust workspace tests, native CPU backend smoke, pinned reference-vector
  tests, and real text/image/audio model tests. Fixture vectors are not proof
  of model quality. Preserve existing cosine tolerances.
- .NET Core/ViewModel/protocol tests and a clean x64 WinUI Release build.
- Real named-pipe end-to-end tests for configuration, exact/semantic search,
  code mode, cancellation, reconnection, pause, and streamed locations.
- Real PDF fixtures including scans and a >30-page interrupted/resumed file;
  actual audio/video fixtures with known timestamps and shot changes.
- Retrieval evals for exact text, OCR, PDF pages, multilingual text, media
  timestamps, code definitions, and negative controls.
- Launch the assembled installed payload outside a source checkout. Confirm
  a responsive top-level WinUI window, engine connection, hotkey, preview,
  settings persistence, model availability, startup, and uninstall behavior.
- Record keyboard, Narrator, high contrast, reduced-motion, multi-monitor/DPI,
  sleep/resume, drive-disconnect, battery/schedule, idle CPU/GPU, and malformed
  file results. Unsupported test hardware remains an explicit pending gate.
- PR description lists audited problems, behavior changes, exact checks,
  measurements, artifact paths, and remaining external gates. No blanket
  claim of full v1.0 readiness while required runtime checks are pending.

## Delivery order

1. Reviewed recovery fixes and repeatable baseline/build harness.
2. Typed durable configuration, consented roots, policy, and parser isolation.
3. Resumable PDF/document processing and real audio/video model pipeline.
4. Opt-in code scheduling, retrieval, and editor routing.
5. Explorer/previews, onboarding, full settings, power/storage/update controls.
6. Release assembly, installer, runtime/evaluation/resource evidence, and PR.

Each slice must have its own passing tests before dependent work. Keep all
changes on `codex/winsearch-v1`; preserve the original checkout and its
uncommitted prior fixes.
