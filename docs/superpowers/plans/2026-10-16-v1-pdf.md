# WinSearch v1 page-level PDF implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make selectable and scanned PDFs searchable at their actual pages, with thumbnails and durable first-pass/continuation progress.

**Architecture:** Extend the existing bounded extraction worker and durable content batches. Load one explicitly pinned PDFium DLL inside that worker, extract page text, and apply existing WinRT OCR to sparse/scanned raster pages. The daemon promotes validated scratch artifacts and commits locations through its existing snapshot checks.

**Tech Stack:** Rust/windows-rs, dynamically loaded PDFium157.0.8086.0, existing WIC thumbnail and WinRT OCR helpers, SQLite durable batches.

**Interfaces:**

Consume extraction worker `ExtractRequest { path, kind, scratch_dir, cursor,
max_units }` and `ExtractResponse { output, next_cursor, total_units }`.
Produce the worker entry point:

```rust
pub fn extract_pdf_batch(
    request: &crate::worker::ExtractRequest,
    budget: &crate::ExtractBudget,
) -> Result<crate::worker::ExtractResponse, crate::ExtractError>;
```

PDF cursor is opaque and forward-only. Use page ordinal plus within-page chunk
ordinal if a large page cannot fit in256drafts; document its encoding and
validation. `total_units` reports real page count capped at the5000page product
limit, with explicit diagnostics when the source has more pages. Process at
most30new pages per batch; response/segment limits can stop sooner. A page is
complete only once all bounded text chunks and requested visual/OCR work are
represented. Do not silently truncate an oversized page and advance to the next.

Every text/OCR draft carries `page: Some(one_based_page)` and its actual excerpt.
Reuse existing numeric exact-only routing. Add a page visual draft when the
page contains meaningful scanned/visual content; share its validated rendered
artifact with the multimodal path rather than passing PDF bytes to an image
decoder. Retain actual thumbnail paths, one primary page thumbnail plus other
matching locations for later preview. Keep no-model exact text searchable.

Pin public dependency metadata exactly:

```json
{
  "version": "157.0.8086.0",
  "tag": "chromium/8086",
  "url": "https://github.com/bblanchon/pdfium-binaries/releases/download/chromium/8086/pdfium-win-x64.tgz",
  "sha256": "1fd8af952832dbb0eb16d9249f68fe09e5f5ebf7c3dd9f6066ea2720cc28487d"
}
```

Fetcher verifies hash before extracting into its explicitly resolved output,
rejects unsafe archive paths, and retains LICENSE plus licenses/*. It does not
modify PATH or install globally. Controller already downloaded and independently
verified this archive under ignored artifacts/dependencies/ for native tests.
Package assembly later copies its DLL/notices beside the extraction worker.

Load only an absolute DLL path derived from the application/dependency location,
with Windows safe search flags; no cwd/PATH fallback. A test-only explicitly
configured absolute dependency directory may supply fixtures. Use pinned
include/fpdfview.h and fpdf_text.h for exact ABI; Windows unsigned long is32bits.
All PDFium calls in one worker run serially with RAII handles. Do not invoke
JavaScript/forms or launch external handlers. Never expose PDFium loading on
the UI thread.

For Unicode source paths use native File plus FPDF_LoadCustomDocument callbacks
if the DLL's path API fails the Unicode fixture; avoid reading the whole PDF
into memory. Bound file offsets/read lengths and account for callback failures.
Use checked dimensions/stride/area, finite positive page sizes and render at
most2048pixels per edge. Raster can then feed existing WinRT OCR and WIC PNG
thumbnail helpers. `FPDFText_GetText` needs an allocated count+1 u16 buffer;
never query it with a null result. Bound extracted text per page and response.
Distinguish protected, corrupt, unreadable, dependency-missing and genuinely
blank PDFs. Preserve committed earlier batches on a later page failure and
report partial failure accurately rather than calling the whole file complete.
