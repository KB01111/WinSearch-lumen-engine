# WinSearch v1 folder and indexing policy implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make normal/code folder selection and indexing policy durable, typed, immediately enforced, and safe for first launch and native tests.

**Architecture:** Add an additive indexing-configuration contract independent from the existing semantic/backend configuration, so an older settings writer cannot reset folder consent. Rust persists and enforces the policy. WinUI controls arrive in the later experience slice; this slice delivers an end-to-end tested engine/client API.

**Tech Stack:** Existing Rust/SQLite/serde/Windows APIs and .NET named-pipe client. No new framework.

**Interfaces:**

Keep protocol version 1 for additive messages. Add to `ClientMessage`:

```rust
GetIndexingConfig { id: RequestId },
SetIndexingConfig { id: RequestId, config: IndexingConfig },
```

Add `ServerMessage::IndexingConfig { id: Option<RequestId>, config: IndexingConfig }`.
Define the canonical wire types in ws-protocol, with serde defaults and snake_case enum names:

```rust
pub struct IndexingConfig {
    pub roots: Vec<String>,
    pub excluded_paths: Vec<String>,
    pub excluded_extensions: Vec<String>,
    pub code_enabled: bool,
    pub code_roots: Vec<String>,
    pub paused: bool,
    pub mode: IndexingMode,
    pub index_on_battery: bool,
    pub respect_battery_saver: bool,
    pub hours_start: u16,
    pub hours_end: u16,
}
pub enum IndexingMode { Always, Scheduled, Manual }
```

Defaults: empty root/exclusion lists, code_enabled false, paused false, Always,
index_on_battery true, respect_battery_saver true, hours_start 60, hours_end 420.
Minutes are 0..1439; equal start/end means all day; overnight windows wrap.
Manual mode runs only when paused is false (the user can start and pause from
the UI). Scheduled mode additionally requires local time inside the hours.
Manual pause always wins; then battery saver, battery policy, and schedule.
Unknown power state must have an explicit deterministic result and a test.

Mirror the contract in C# (`IndexingMode`, `IndexingConfig`), adding
`GetIndexingConfigAsync`, `SetIndexingConfigAsync`, and `IndexingConfigChanged`
to `IEngineClient`, `EngineClient`, and FakeEngineClient. Use the existing
framing, unary dispatch, cancellation, and typed protocol conventions.

Expose the following Rust controller APIs (return the existing StoreError or
an explicit validation error suitable for InvalidRequest):

```rust
Indexer::get_indexing_config(&self) -> Result<IndexingConfig, StoreError>
Indexer::set_indexing_config(self: &Arc<Self>, config: &IndexingConfig) -> Result<(), StoreError>
Indexer::indexing_pause_reason(&self) -> Option<String>
Indexer::content_path_allowed(&self, path: &Path) -> bool
```

If validation cannot use StoreError without distorting it, introduce a small
policy-specific error at the controller boundary and document its exact type
in the report. Do not convert invalid input into a successful no-op.

Normal-root membership uses case-insensitive Windows component boundaries:
`C:\Data` does not include `C:\Database`. Explicit chosen subroots can opt
back into a skipped ancestor, matching upstream FolderSelection behavior.
Reject relative, NUL-containing, and excessive lists (at most 128 roots of
each kind, 512 excluded paths, 256 extension rules). Preserve missing/offline
absolute roots so removable drives remain configurable. Validate extension
rules as lowercase extensions without a dot (normalize a single leading dot).
Preserve existing sensitive/reparse/cloud rules as mandatory restrictions.
Audit correction: the current crawler's comments promise no cloud hydration,
but no content-open gate checks cloud attributes. Add a shared metadata-only
guard before every content/preview/embedding open. A file with OFFLINE,
RECALL_ON_OPEN, or RECALL_ON_DATA_ACCESS attributes must remain name-only;
never open it to inspect its content. Reject reparse-point traversal, including
configured roots and ancestor paths. Test flag decisions without a real cloud
provider and use actual local symlink/junction fixtures where supported.

Normal content extraction must also honor upstream project/dataset policy:
inside recognized code projects, read screenshots only outside opted-in code
search; do not extract repository documents/configuration as ordinary user
content. Reuse ws-code's existing project/secret rules where applicable.
Match the upstream Rules.swift dataset rule using metadata: a non-explicit
subfolder with at least 300 media files of the same kind and at least 70%
machine-like names is name-only, with an explanation usable by later UI.
An explicitly selected root is never rejected as a dataset. Camera prefixes
img,dsc,pxl,mvimg,vid,gopr,dji,photo,whatsapp,screenshot are not machine-like.
Machine-like stems are long hex IDs or a short alphabetic prefix followed by
at least three digits (for example clip_000123). Do this during bounded
directory enumeration; never read content to classify. Test the300/70%
boundaries, explicit root override, a camera roll, and a normal document folder.

Store the entire validated policy atomically (one JSON record) together with
active root visibility changes. Existing index rows are preserved on removal,
but their names/content/vectors disappear immediately from results and cannot
be claimed/committed by background workers. A later re-add rescans/reconciles.
The synthetic application-catalog root remains available without folder
consent. Ensure search limits are applied after policy filtering rather than
letting disallowed candidates crowd out permitted results.

Fresh startup loads stored policy and uses an empty default. Migrate legacy
root rows into an explicit stored policy once, preserving existing behavior
and data, without adding previously unindexed standard folders. Existing
`Indexer::open(store, roots)` remains useful for explicit test fixtures; main
must no longer call profile-default root discovery. Replace watchers safely
outside locks held by callbacks; in-flight stale scans/extractions must check
the current policy before committing. Avoid deadlocks during root changes.

All normal crawl/name-embed/content-extract workers consult pause policy
before claiming new work. Queue depth remains durable while paused. Emit
Paused status with the actual reason and retain exact interactive search.
Use bounded waits and native power/local-time readings with pure decision
logic. Idle workers must not busy-poll; background supervisors may use their
existing coarse cadence. Notify waiting workers when configuration changes.

Add `WINSEARCH_DATA_DIR` as an absolute-path override in both Rust paths and
C# AppSettings so integration tests can run entirely in generated fixtures.
App/engine child launches inherit it. An invalid relative override must fail
clearly rather than silently placing data in the checkout. Default user paths
are unchanged when it is absent.

Data-path isolation alone does not isolate the existing per-user pipes and
instance guards. Add a test/development `WINSEARCH_INSTANCE_ID` override,
validated as1..48ASCII letters/digits/underscore/hyphen, and apply the same
optional suffix to daemon/embed pipe names, Rust engine/embed mutexes, and
C# app/show-event names. Include SID in existing per-user naming consistently.
Preserve the current default names when the override is absent for upgrade
compatibility. All child processes inherit it. Invalid values fail clearly.
Test two instances with different IDs and data directories concurrently; no
IPC, activation, locks, or shutdown may cross into the other instance. This
allows native app checks without touching a user's running WinSearch session.
